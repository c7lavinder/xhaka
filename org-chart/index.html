Scope & Eligibility Check
Owner: New Lead Process Supervisor
Intelligence

GHL fires a webhook for every contact that enters "New Lead" stage — buyers, JV partners, random imports, duplicates, everything. Without this check, the agent would run its full process on all of them. In V1, this is exactly what caused buyers to get seller workflows. This step is the bouncer at the door — only the right contacts get through.
Check 1
Seller Pipeline Only
The system reads which pipeline the contact is in. For NAH, being in the Sales Process pipeline is the definition of a seller lead — there's no separate tag or field. Pipeline membership IS the classifier.

For other customers, they map their pipeline during onboarding. The agent never uses a hardcoded name — it reads from tenant config, so "Acquisitions," "Motivated Sellers," or anything else works identically.
Config: sellerPipeline.id
Check 2
Correct Stage Only
Confirms the contact just entered the configured entry stage — not that they were already sitting in it, or moved to a later stage. This prevents the process from re-firing on leads that already exist in the system and got moved around internally.

Stage is also mapped during onboarding via dropdown — no hardcoding.
Config: newLeadStage.id
Check 3
Idempotency
Looks up whether this exact agent already ran on this contact recently. GHL sometimes fires duplicate webhooks — this check prevents the same lead from being processed twice, double-texted, or getting two LM tasks.

Fingerprint = contact_id + agent + action + time_window
Window: 24h for SMS, immediate for pipeline moves
Check 4 — sets a flag
Returning Lead Detection
Checks if this contact has been through the system before. If yes, they're marked as a returning lead permanently on their record.

Every downstream step reads this. The lead still comes through all 4 steps — but the content changes: different SMS tone, prior conversation briefed to LM, scoring uses history. The structure is identical, the execution is smarter.
Stored in: contact_context table
Check 5 — the one hard stop
Has Phone OR Email
The only check that fully halts the process. If there is no phone number and no email address, there is nothing the agent or the LM can do — the lead is unreachable.

Hard stops are never silent. The halt is logged and surfaces immediately in the Needs Attention panel in Gunner — showing the contact name, what's missing, and a direct link to fix it in GHL. The lead stays in New Lead stage untouched. Team member adds the missing contact info, marks it resolved — agent re-triggers and runs the full process. Everything else the agent works around. This is the one gate.
Phone OR email → proceed  ·  Neither → hard stop → stays in New Lead → Needs Attention panel
💡 Checks 1–4 fail silently — wrong pipeline, duplicate, out of scope. No action needed, agent moves on. Check 5 is the only visible failure — it logs a hard stop and requires a human to fix it before the lead can be processed.

Handoff
→ Lead Scorer Sub-Agent
Garbage in, garbage out. If the Lead Scorer runs on a contact with a malformed phone number, wrong timezone, and no source label — the score is unreliable and the LM task is incomplete. Data Hygiene runs first so every downstream step works from clean, standardized data. It also pulls information the system needs that wasn't on the original form — mailing address, timezone, market. Nine utility bots run in sequence. Each does exactly one thing. All are reusable across the system. Nothing halts — if a bot can't complete its job, it logs it and moves on.
Bot 1
Phone Cleaner
Strips symbols, spaces, and dashes. Standardizes to a consistent dialable format. Ensures the SMS Bot and Task Bot always have a clean number to work with.
Bot 2
Timezone Bot
If a property address is present, geocodes it and looks up the timezone from the coordinates. If no address, falls back to deriving timezone from the phone area code. Property location is always preferred — absentee owners may live in a different timezone than their property.
Bot 3
Market Identifier
Matches the property address or zip code to the tenant's configured market list. Tags the contact with the correct market. Market list is defined per-tenant during onboarding and managed by Corey at the platform level.
Bot 4
Source Normalizer
Cleans up whatever source label came in from GHL. "ppl", "PPL", "Pay Per Lead", "pay-per-lead" all become the same standard label. Keeps scoring and reporting consistent across all leads regardless of how they were entered.
Bot 5
Name Formatter
Fixes capitalization on first and last name. JOHN SMITH → John Smith. john smith → John Smith. Every SMS, task, and note needs to read cleanly — this makes sure it does.
Bot 6
Email Formatter
Lowercases the email, strips leading/trailing spaces, and validates it looks like a real email address. Flags it if it doesn't pass basic format validation — but never halts.
Bot 7
Timestamp Bot
Logs the exact moment the lead entered the system. This is how SLA compliance is tracked — did the LM call within 15 minutes? Without a clean submission timestamp, there's nothing to measure against.
Bot 8
Mailing Address Bot
Hits the BatchLeads API with the property address to look up the seller's mailing address (where they actually live — often different for absentee owners). Writes the mailing address fields back to the contact if found.
Bot 9
Business Name Bot
Sets the GHL "Company" field to the property street address. Standard wholesale trick — it makes the property address visible in pipeline card views and list exports without needing a custom field column.
Bot 10
Property Data Bot
Hits BatchLeads with the property address and pulls everything available from public records: property type (SFR, MFR, mobile home, land), bed/bath count, square footage, year built, last sale price + date, tax assessed value, equity estimate, and owner type (individual, LLC, absentee). Writes all of it to the contact before Lead Scoring runs — so the scorer never has to hunt for data, it just evaluates what's already there. Also sets the Property Type and Owner Type tags.
Bot 11
Lead Intel Bot
Reads every available source to extract intel — condition, timeline, motivation, and asking price — before Lead Scoring runs. Source-aware: checks the lead's source tag and knows where to look.

GHL / Form notes → reads directly
Dialer lead → hits the Dialer Adapter (BatchDialer for NAH, swappable) — pulls disposition and call notes
SMS lead → hits the SMS Adapter (BatchLeads for NAH, swappable) — pulls conversation thread
Condition fallback → if no condition found in any notes, pulls Google Street View and estimates from exterior

Different customers use different dialers and SMS platforms — the adapter pattern means swapping platforms requires no changes to this bot. If a tenant's platform isn't supported yet, it falls back to GHL notes only and flags the gap.
💡 After all 11 bots run, the Note Bot writes a clean summary to the contact: what was pulled, what was already there, what's still missing. The LM sees exactly what the system found and what they need to gather on the call.

Lead Scoring
Owner: Lead Scorer Sub-Agent
Intelligence
Lead Scorer Motivation Analyzer
Bots
Tag Bot Note Bot Pipeline Bot
Rules
Scoring weights (Playbook) Hot / Warm threshold
Output
HOT or WARM tag set Score + reasoning noted Team member assigned
Handoff
→ Responder Sub-Agent → Task created for LM (both fire in parallel)
Without scoring, every lead gets treated the same — and they're not. A seller 30 days from foreclosure needs a completely different response than someone casually wondering what their house is worth. The score tells the system and the LM how urgently to move. HOT leads get urgent tasks and a different outreach tone. WARM leads get standard tasks. The LM opens their task already knowing what they're walking into — before they dial. Without this, they're flying blind on every call.
Intelligence
Lead Scorer
Evaluates the lead across multiple factors — timeline, motivation signals, source quality, and anything gathered in Data Hygiene. Produces a HOT or WARM score with reasoning. Weights come from the Playbook and improve over time as tenant data accumulates.
Intelligence
Motivation Analyzer
Reads any available text — form responses, notes from the lead source — and identifies motivation signals. Distress language, urgency, financial pressure. These signals feed directly into the Lead Scorer's output.
Bot
Tag Bot + Note Bot + Pipeline Bot
Tag Bot applies HOT or WARM. Note Bot writes the score and reasoning to the contact so any team member can see why it was scored that way. Pipeline Bot moves the opportunity to the correct stage (Hot Leads or Warm Leads) and assigns it to the right team member.
Returning Lead
Scoring uses history
For returning leads, the scorer has additional signal — prior motivation score, what changed since last contact, how they re-entered (them calling back is a strong signal). The score is weighted differently from a first-time lead and the reasoning reflects that.
💡 There is no COLD score — only HOT and WARM. A lead that scores low is still a lead worth working. It gets a standard task, not no task.

Initial Outreach + LM Task
Owner: Responder Sub-Agent  ·  runs in parallel
Intelligence
Message Crafter Tone Matcher
Bots
SMS Bot Email Bot Task Bot
Rules
Phone → SMS first No phone → Email fallback Send window (8am–8pm) Returning lead — skip intro 24h idempotency
Output
First message sent (SMS or Email) Task: "[name] — [score] — [source]" Task includes missing field list
Handoff
Human: LM sees task, calls lead "Missing: address — get on call"
Speed to lead is one of the highest-leverage actions in wholesale. Response rates drop dramatically within the first few minutes of a lead coming in. This step fires immediately — the seller hears from someone within seconds of entering the system, and the LM gets a task at the exact same moment. Both happen in parallel. Waiting for one before starting the other would cost minutes that matter.
Channel Priority
Phone → SMS. No phone → Email.
If the lead has a phone number, SMS goes out immediately — highest response rate. If no phone but has email, an email goes instead. Both channels produce a message tailored to the lead — not a template blast. If neither exists, this step was already blocked at Step 1.
Intelligence
Message Crafter + Tone Matcher
The message isn't a static template. Message Crafter writes it based on source, score, available data, and time of day. Tone Matcher adjusts the wording — a morning message reads differently than an evening one. Returning leads get a relationship message, not an intro.
LM Task
What the LM sees
The task includes: contact name, score (HOT/WARM), source, and a list of any missing fields to gather on the call. The LM doesn't have to dig through the contact — everything they need to prepare for the call is in the task description.
Returning Lead
Different message, same speed
Returning leads skip the intro. The message references the relationship — "Good to hear from you again" — and the LM task includes a summary of prior conversations so they're briefed before dialing. Same urgency, smarter execution.
💡 The send window rule (8am–8pm) applies to SMS and Email. If a lead comes in at 2am, the message queues and fires at 8am. The LM task still gets created immediately so it's ready when they start their day.

The agent's entire job up to this point was to make this call happen as fast as possible. Now the human takes over. AI cannot replace the first real conversation with a seller — it requires listening, empathy, and real-time judgment. The LM qualifies the lead, gathers missing information, builds rapport, and decides the next step. This is where deals are won or lost.
SLA
15 minutes from task creation
The LM should be dialing within 15 minutes of the task appearing. At 30 minutes with no activity, it escalates to Jessica so nothing gets missed. Speed to lead doesn't end with the SMS — the human call needs to follow quickly.
LM's job on the call
Qualify, gather, decide
Confirm the property situation. Get the address if missing. Understand timeline and motivation. Gauge interest in selling. Determine next step — appointment, follow-up, or not a fit. Everything the agent couldn't get from the form, the LM gets on this call.
💡 The LM task includes everything the agent knows — score, source, missing fields, prior conversation if returning lead. The LM should read the task before dialing, not after.

After every call, a good LM should be updating the CRM, writing notes, creating follow-up tasks, and moving the pipeline. In practice this is inconsistent — things get missed, notes are vague, tasks don't get created. The LM Assistant fires immediately when the call ends and does all of it automatically, every time, with no variation. The LM gets credit for the conversation. The system handles everything after.
Intelligence
Call Summary + Disposition + Next Step
Reads the call transcript. Writes a clean summary. Determines the call disposition (appointment set, follow-up needed, not interested, etc.). Recommends the next step based on what was said. All three run together and feed the bots that execute.
Routing
Where it goes next
If an appointment was booked → hands off to Acquisitions Supervisor. If the seller needs more time → hands off to Follow Up Supervisor. If it's not a fit → closes out cleanly with a note. The stage move and next task reflect exactly what was decided on the call.
💡 Confidence threshold applies here. If the agent is unsure about the disposition or next step, it flags it for the LM to confirm rather than executing automatically.

Working Drip — Contact Attempt Sequence
Owner: Responder Sub-Agent
Intelligence
Message Crafter
Bots
SMS Bot Task Bot
Rules
SMS window (8am–8pm) 104-day max sequence Stop on first reply or contact Daily attempt limit
Output
Drip sequence initiated Call tasks queued for LM
Handoff
Human: LM works call tasks → Back to Step 5 on contact → Follow Up Supervisor if sequence exhausted
Most leads don't answer the first call. Or the second. The national average in wholesale is 7+ contact attempts before reaching someone. Without a structured sequence, no-answer leads fall through the cracks within days — the LM moves on to fresh leads and forgets about them. The Working Drip ensures systematic contact attempts for up to 104 days. Every attempt is logged. Every SMS is tracked. The sequence stops the moment contact is made. Nothing gets forgotten.
What it does
SMS + Call Tasks in sequence
Fires a series of SMS messages and creates call tasks for the LM at defined intervals. The LM keeps attempting the call. The agent keeps sending messages. Both stop the instant the seller responds or picks up — at which point it loops back to Step 5 and the LM runs the conversation.
Sequence end
104 days, then Follow Up
If 104 days pass with zero contact, the lead is moved to the Follow Up Supervisor. It's not dead — it's just been reclassified as a long-term nurture lead. Follow Up handles it from there with a different cadence and different messaging strategy.
💡 The send window rule applies to every SMS in the drip. No messages go out between 8pm and 8am regardless of when the sequence timer fires.
