# Gunner Engine Audit — 2026-02-18 (3:17am CST)

## Summary
Audited all 10 active engines + pollers + scheduler + startup. Found and fixed **2 bugs**, one of which was **critical** (would crash on real leads).

---

## Bugs Found & Fixed

### 🔴 BUG 1: Pipeline Poller → Data Hygiene call signature mismatch (CRITICAL)
**File:** `src/pollers/pipeline-poller.js` line 156
**Issue:** Called `getConfig()` which is NOT exported from `data-hygiene/index.js`. Would throw `TypeError: getConfig is not a function` when a real lead enters "New Lead" stage with `ENGINE_DATA_HYGIENE=active`. Also passed 5 args to `processContact()` which only takes 4 — `hygieneConfig` was passed where `state` should go.
**Fix:** Removed `getConfig` import and extra arg. Now calls `processContact(hygieneGhl, contact, hygieneState, 'default')` matching the 4-arg signature.
**Impact:** Without this fix, every new lead entering the pipeline would fail Data Hygiene → Lead IQ chain silently (caught by try/catch), meaning NO scoring, NO assignment, NO SMS response.

### 🟡 BUG 2: New Lead Responder quiet-hours SMS has no message text (HIGH)
**File:** `src/engines/new-lead-responder/index.js` lines 215-235
**Issue:** Two problems:
1. Used `delayUntil` instead of `sendAfter` — Message Queue ignores unknown keys, so held messages would send immediately instead of at 8:05am.
2. No `smsText` in the queued message — the message body is built AFTER the early return, so quiet-hours leads get queued with `smsText: undefined`. Message Queue skips sending when `msg.smsText` is falsy.
**Fix:** Moved message construction (firstName, branch, variation, buildMessage) above the quiet-hours check. Changed `delayUntil` to `sendAfter`. Added `smsText: heldMessage` to the queue call. Uses 'morning' variation since it sends at 8:05am.
**Impact:** Without this fix, any lead arriving between midnight and 8:05am CST would never receive the initial SMS response.

## Audit Results (All 12 Checks)

### 1. Import Chain ✅
All `require()` paths in all 10 engine files resolve correctly. No missing modules.

### 2. ENGINE_KEY Mapping ✅
`isDryRun()` in `dryrun-log.js` correctly maps: `isDryRun('new_lead_drip')` → checks `ENGINE_NEW_LEAD_DRIP` env var. All 10 engines listed in `getEngineStatuses()`. The `new_lead_responder` key is in the list.

- Pipeline poller detects opps → triggers Data Hygiene on "New Lead" stage

- Detects inbound messages → Message Queue handoff check, Message Intelligence tracking
- Triggers New Lead Drip enrollment via `analyzeConversationForDrip()`

### 6. Message Queue Send Path ✅
- `queueMessage()` validates contactId, deduplicates (2h window), persists to disk

- Resolves `userId` from `msg.assignedTo` or fetches from contact, passes to `ghl.sendSMS()`/`ghl.sendEmail()`
- Pre-send safety: checks for inbound activity since queue time, cancels if found

### 7. New Lead Responder ✅ (after fix)
- Routes through Message Queue with `priority: 'high'`

### 8. New Lead Drip ✅

### 9. GHL Client ✅

- New Lead Drip: every 5 min (`runNewLeadDripFast`)

### 11. Startup ✅
