# Proposed Changes

Auto-generated by the Researcher and Inspect jobs when an article insight or root cause analysis maps to a behavioral gap.

## Review Process
1. Xhaka reviews each morning (see HEARTBEAT.md)
2. Approved → route to Builder with file path + proposed change text
3. Rejected → move file to `rejected/` with a one-line comment
4. Implemented → Builder moves to `approved/` after commit

## Confidence Filter
Only HIGH confidence proposals are written here.
MEDIUM/LOW are logged in Railway but not persisted.

---

## Applied Change Format (Builder Instructions)

When Builder applies a proposed change, it **must** add two sections to the change file before moving it to `approved/`:

### Section 1 — Applied Metadata
```markdown
## Applied
applied_at: 2026-03-14T15:00:00.000Z
before_score: 72
applied_by: builder
```

- `applied_at`: ISO 8601 timestamp of when the change was committed to the repo
- `before_score`: The last score from `data/evaluation-log.json` for the target job, recorded BEFORE the change was applied
- `applied_by`: Always `builder`

### Section 2 — Current State (REQUIRED for rollback)
```markdown
## Current State
```typescript
// paste the FULL original file content here BEFORE the change
```
```

> ⚠️ **Critical:** Without `## Current State`, automatic rollback is impossible.
> If a regression is detected and this section is missing, Corey will receive a manual intervention alert.

### Complete Applied Change Example
```markdown
# Proposed Change — 2026-03-14
Source: Inspect job (root cause analysis)
Target: services/intelligence/src/jobs/researcher.ts
Type: fix

## Root Cause
...

## Recommended Fix
...

## Current State
```typescript
// [original file content pasted here]
```

## Applied
applied_at: 2026-03-14T15:00:00.000Z
before_score: 72
applied_by: builder
```

## Evaluation & Rollback
After a change is applied and the target job runs once, `change-evaluator.ts` automatically:
- Reads `before_score` from the change file
- Reads the first post-apply score from `data/evaluation-log.json`
- Computes verdict: **IMPROVEMENT** / **NEUTRAL** / **REGRESSION**
- Writes result to `intelligence/change-results/YYYY-MM-DD-{slug}.md`
- On REGRESSION: triggers `rollback.ts` to restore the original file and alerts Corey
